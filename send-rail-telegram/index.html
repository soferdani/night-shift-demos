One card a night, and one tap writes the answer into the vault

send-rail finds the messages that are written, addressed to a real person and never sent. The page version waits on a laptop. This is the other front end: the single message to open now, pushed to a phone, with the taps on it.

Night 3. Until tonight the rail read one convention: a heading saying the text below it is ready to paste. That convention is also the horizon — a finished thing addressed to a named person is not always a message. Sometimes it is the document itself, and there is nothing to paste because the note is the deliverable. Four of those were sitting in the real vault, the oldest written 87 days ago and marked ready to send, and no run before tonight had ever looked at them. The last card below is one. Nothing is ever sent by the program.

The card arrives with a keyboard whose buttons are shell lines, so a tap sends a line Doorman already runs and the answer is written under the draft and committed. Tap one and watch the note.

Coursework is refused on the vault's own course: field, and that test earns its place on the shape of what it stops rather than on a count here: this vault keeps thirteen notes of a classroom crisis simulation, each a finished document addressed to a named person who does not exist, and the rail's config happens to skip that whole folder already. A card addressed to one of them at 22:00 is how a man learns to stop reading the card, so the test stays — for the next piece of coursework filed somewhere the config does not cover.

Sample data, a made-up vault — the real one is private. Everything you see runs in this page; the actual tool is Node, zero dependencies, 259 tests, and it reads the vault without writing to it except for the one verdict line you tap here.

Why the button is a shell line. Telegram lets one program at a time read a bot's replies, and Doorman — the bridge that has been on the box since September — holds that. A reply-keyboard button is neither a link nor a callback: tapping it sends its own text into the chat, from you. So the button's text is a line Doorman already runs, and the loop closes with no second bot, no token to create and no file of Doorman's to patch. The token the card is posted with is Doorman's own; posting was never the exclusive part.

Three things tonight's run found in its own detector. The first version read בלוג — סוכן AI פרץ ל-Hugging Face (עברית) and reported that somebody called Hebrew had been waiting 79 days for a blog draft — a bare word in brackets is a language, a version or a variant as often as a surname, so a name found there now has to carry a first name and a last name. Fixing that let the next one through: the same lane accepted a Hebrew solution-principles document as owed to a person called “עקרונות הפתרון”, which is the words “solution principles”. Every test under it leaned on a capital letter, and Hebrew has none — so the title lane is Latin-script only now, and that is a stated limit rather than a silent one. And the write-back would have stacked a second footer under the first on every repeat answer to a document, because the record of what was posted never said which of the two kinds the card was.

What the run found in last night's code. The verdict line was being welded onto the last line of the message whenever the note already had a blank line after the draft — which is most of them — so Obsidian drew sent on … as a callout nested inside the signature. Last night's tests could not see it: they all went through the scanner, and the scanner is the one reader that refuses to absorb a callout. Separately, the nightly script's once-a-night guard searched its log for a line it could never match, because the logger stamps the time in front of everything it writes.

Why a document does not compete for the top card on age alone. The rail's own rule in clear to send is freshest first, because an old unsent message has probably stopped being true. That is a claim about text, and the three detectors that make it — a date that has gone by, a sentence about now, a line written under the block — are deliberately not run on a document: a ten-thousand-character implementation path contains “this week” somewhere and is not thereby unsendable. So documents sort oldest first among themselves, and take no position in front of a message.

Why a draft sometimes arrives in two messages. A 652-character Hebrew email percent-encodes to about 5,800 characters of URL, and no Telegram button takes a link that long. Those get an addressed compose window plus the text as a tap-to-copy message. The invoice card below shows it.

sent writes a mark the scanner has read since night 1, so the draft leaves the list by the road that was already there. skip must not look like that mark — a skipped draft that quietly stops being offered is the exact failure this tool exists to prevent — so it holds the card for fourteen days and then the draft is back. dead is still not a delete.
